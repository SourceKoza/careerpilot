# Goal

Implement the Resume Management module.

This sprint introduces the concept of a logical Resume and immutable Resume Versions.

A Resume represents a long-lived document owned by a user.

A ResumeVersion represents a snapshot of that resume at a specific point in time.

Every future Job Application must reference a ResumeVersion rather than the Resume itself.

This design preserves history and supports AI-generated resume tailoring.

---

# Business Requirements

A user can own multiple resumes.

Examples:

* Java Backend Resume
* AI Engineer Resume
* Full Stack Resume

Each resume can have multiple versions.

Editing a resume creates a new ResumeVersion instead of modifying an existing one.

Previous versions must never be changed.

Represents an immutable snapshot.

* id

* versionNumber

* pdfPath
* changeSummary
* createdAt

Version number must be generated by the system.

Markdown content cannot be empty.

A ResumeVersion cannot exist without a Resume.

# Production Considerations

ResumeVersion must be immutable.

Never update existing ResumeVersion records.

Every new edit creates a new version.

This enables:

* Audit history
* AI resume tailoring
* Historical job applications
* Rollback to previous versions
